What it does

The phone owns no files. It shows what your Mac shares with it and what other people beam to it.

read-only

Reads, never edits

HTML and Markdown render the same way as on the Mac. The phone cannot create, rename, or delete anything in your workspace.

paired Mac

Pulls from your Mac

Open a skypies:// link on the phone and it fetches the file straight from the Mac it lives on, over an end-to-end encrypted link. No upload, no server.

beam

Receives Beams

Anyone with skypies can send you one artifact behind a skypies://receive link. You confirm before the phone fetches it.

Pairing

You pair once per device. The Mac shows a QR code; the phone scans it. Both screens then show the same six words.

  1. Start on the Mac

    Settings → Remote → Pair a device…. The Mac shows a QR code and a pairing link. The invite expires after a short time.

  2. Scan on the phone

    Scan the QR code with the camera, or open the link on the phone. skypies for iPhone opens the invite.

  3. Compare the six words

    Both screens show six words. Read them on one screen and check them on the other.

    orbitmaplecandleriverpixelharbor

  4. Confirm on both

    Confirm only when the words match. From then on the phone appears in the Mac's device list and can pull files from it.

Why the words matter The six words are the fingerprint of the encrypted link. If they differ, something sits between the two devices. Do not confirm; start again.

Receiving a Beam

From a stranger or a colleague

A Beam is one artifact served directly from the sender's machine for a limited time. The sender does not need to be paired with you.

  • You open the skypies://receive link on the phone.
  • The phone shows the file name and size and asks you to confirm.
  • The file lands in the app's own Received list, never in a workspace.
  • The sender can stop the Beam at any time; after that the link is dead.

Received content is untrusted

A beamed HTML file was written by someone else. The phone renders it in an isolated view with scripts and local access cut off, the same rule the Mac app follows.

  • No access to other files on the device.
  • No network from inside the artifact.
  • A "beamed" badge marks it in the list.

Reading and comments

One column: title, the artifact full-bleed, and a bar at the thumb. Library and open tabs are bottom sheets.

Comments go back to the Mac

Select text or tap a spot on an image and leave a comment. For a file pulled from a paired Mac, the comment syncs back to that Mac, so the agent that wrote the file can read it with list_feedback and mark it addressed with resolve_feedback.

  • Comments are the only thing the phone writes, and they land in the app's state directory, never beside the file.
  • Sync works in both directions while both devices are online.

What the phone shows

  • Start screen: a Received pie plus one Shared from <Mac> pie per online Mac.
  • Tap a pie to open its file list; tap a file to read it.
  • A tab pulled from a Mac says so under its title.
  • Back and forward per tab, like the Mac app.
